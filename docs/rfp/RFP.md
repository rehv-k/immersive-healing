## 1. 문서 개요

### 1.1 목적

MRD가 검증한 시장 요구사항(MR-1~18)을 바탕으로, **1호 콘텐츠 MVP를 만들기 위해 다음 단계에서 무엇을 제안·결정해야 하는지**를 정의한다. 이 문서는 아래 질문에 답할 제안을 요청한다:

1. 어떤 기술 스택으로 만들 것인가? — **아직 확정되지 않았으며, 본 RFP는 비교 조사를 명시적으로 요구한다** (§5.A)
2. 어떤 공간·경험으로 연출할 것인가? (§5.B)
3. 콘텐츠(영상·사운드)를 어떻게 수급·가공·배포할 것인가? (§5.C, §5.D)

### 1.2 범위

- **포함**: 1호 콘텐츠 **일몰(sunset)** 을 완결된 경험으로 제공하는 MVP — 입장 연출부터 관람·퇴장까지.
- **제외**: 콘텐츠 확장 체계, 여러 전시실(박물관 형태), 모바일 지원, VR 헤드셋, 동시 관람, 수익화, 재방문 훅(시간대 연출 등 — MR-17). 이들은 §7의 향후 로드맵 참고로만 언급한다.

## 2. 프로젝트 배경 (요약)

- **비전**: 박물관 실감영상관의 압도적 시청각 경험을 웹 브라우저에서 — 그 경험을 통한 힐링. 고정 화면의 "시청"이 아니라 공간에 "입장"하는 경험.
- **시장 근거 (MRD 핵심 결론)**:
  - 오프라인 몰입 전시 수요는 검증됨(국중박 2025년 650만 명, 아르떼뮤지엄 누적 1,000만 명). 그 온라인 대응은 유튜브 360 수준에서 정체.
  - "웅장한 공간감 + 자유 이동 + 공간 사운드 + 힐링 목적 + 무료 웹" 5요건을 모두 갖춘 직접 경쟁자 미확인 — 포지션은 **"움직일 수 있는 힐링(walkable healing)"**.
  - VR 미지원은 연구로 정당화됨(평면 스크린과 VR의 스트레스 감소 효과 유의차 없음). 유효 성분은 "시청각" 노출 — 사운드는 장식이 아닌 핵심 성분.
- **확정된 경험 설계 (GOAL 4.5)**: WASD 자유 이동(클릭 이동 없음) · 1인 관람 · 입장 연출(찾아가는 과정) · 상영 구조는 콘텐츠를 따라감.
- **v1.1 추가 근거 (조사 F)**: 비-VR 모니터 환경에서도 1인칭 멀미는 인접 조건 실험에서 40% 이상 보고되며, 멀미는 부정적 정서 증가·즐거움 감소와 직접 상관 — **멀미 저감은 힐링 목적의 하한선(gate)이다.** 단, 멀미 제거는 힐링의 필요조건이지 충분조건이 아니다.

## 3. MVP 요구사항

MRD의 시장 요구사항(MR)을 MVP 범위로 옮긴 것. 기술 중립적으로 서술하며, 구체 구현 방식은 제안(§5)의 몫이다.

### 3.1 경험 요구

| ID | 요구 | 근거 |
|---|---|---|
| R-1 | 관람자는 3D 공간을 WASD + 마우스 시점으로 자유롭게 걸을 수 있다. **방향키 병행 지원 필수**, 키 입력은 물리 키 위치 기준(`KeyboardEvent.code` 상당)으로 처리해 키보드 레이아웃·한글 IME 상태와 무관하게 동작한다 | MR-1, 조사 E |
| R-2 | 이동·카메라 조작감은 상용 게임 수준(충돌, 시야각, 프레임타임 일관성). **[v1.2 재정의]** MR-2의 "관성"은 멀미 저감 요구(R-14 등속)와 충돌하므로 조정한다 — 부드러움은 관성이 아니라 **짧은 입력 램프(≤80ms)·마우스 원델타 직결·일관된 프레임타임**으로 달성한다. 벽 끼임·미끄러짐·급격한 카메라 없음. **마우스 스무딩·가속은 기본 꺼짐** — 입력과 카메라 움직임의 불일치는 멀미 유발 요인 | MR-2(조정), MR-2↔MR 충돌 조정 기록, 조사 F |
| R-3 | 소리는 방향과 거리를 가진다(정위 오디오). 스크린에 다가가면 소리가 커지고, 고개를 돌리면 방향이 바뀐다. 동시 정위 음원은 소수(4~8개)로 제한, 배경 앰비언스는 스테레오 | MR-3 |
| R-4 | 공간의 규모감(웅장함)이 입장 직후 첫 시야에서 전달된다 | MR-4 — "하얀 방에 액자"는 실격 |
| R-5 | **입장 게이트("입장하기" 클릭)는 필수 구조** — 브라우저 보안 정책상 오디오 시작과 마우스 시점(Pointer Lock) 모두 사용자 클릭 없이는 불가능하므로 우회 불가. 게이트에 헤드폰 안내를 통합하고, 이후 찾아가는 입장 연출로 이어진다 | MR-5, MR-9, 조사 E |
| R-6 | **Esc = 일시정지**: Esc로 시점 잠금이 풀리면 일시정지 메뉴(오버레이)가 나타나고, 클릭으로 복귀한다. Esc 직후 즉시 재진입은 브라우저가 막으므로 이 루프를 UX로 흡수한다 | 조사 E — 업계 표준 패턴 |
| R-7 | 짧게 머물러도(2~3분) 완결감이 있고, 원하면 길게 켜둘 수 있는 이중 구조. **[변경 2026-08-22 — 사용자 결정, 코드 역반영]** 소리는 **탭을 보고 있을 때만** 재생한다(백그라운드 전환 시 페이드 아웃, 복귀 시 페이드 인). 기존의 "백그라운드 오디오 지속(켜두기)" 요구는 폐기 — MR-12의 '켜두는 힐링'은 탭을 띄워둔 상태의 장시간 관람으로 재해석 | MR-12(재해석), 조사 E |
| R-26 | **[v1.3 신설 — 사용자 방향 전환]** 관람 공간은 **입구를 제외한 벽 전체가 하나의 연속된 스크린으로 관람자를 감싸는 곡면 홀**이어야 하며, 관람자와 벽 사이에 시선을 가리는 구조물이 없어야 한다. 바닥(과 가능하면 천장)은 스크린의 빛을 **반사·연장**하여 영상이 발밑까지 이어지는 느낌을 주어야 한다. 국립중앙박물관 실감1관(폭 60m×높이 5m 파노라마 + 바닥 투사 + 서라운드)의 원체험을 기준 레퍼런스로 삼되, 홀의 구체 형상(타원 등)과 치수는 설계가 정한다 | MR-4, MR-5, 조사 K §1.1·§2 |

| R-21 | **영상은 다중 해상도 렌디션(720p/1080p/1440p 3종)으로 제공**하고 성능에 따라 적응 선택한다. 하한 장비 기본값은 1080p. **[v1.2] 2160p는 제작하지 않는다**(Cloudflare 무료 캐시 상한 512MB — 480MB로 94% + 하한 장비 기준 수요 극소, 감사 D3 결정). **렌디션 파일은 각 400MB 이하** 하드 제약. 코덱은 H.264 단일 — MR-18의 듀얼 코덱(AV1)은 MVP 범위 제외(무료 에그레스 환경에서 절감 실익 없음, 트래픽 과금 CDN 전환 시 재검토). 소스 프레임레이트 30fps 상한 | 조사 G·감사 A2 — MVP 최대 기술 리스크 |
| R-22 | **모든 미디어 소스(영상·사운드)**: 사운드는 CC0 우선, 필요 시 CC-BY 허용(크레딧 페이지 운영), CC-BY-NC 배제. 영상은 무료 스톡 라이선스의 "원본 그대로 재배포 금지" 조항에 유의(MR-11). 모든 소스의 출처·라이선스 기록 관리 | MR-11 |
| R-27 | **[v1.3 신설]** 콘텐츠는 **시간의 흐름을 가진 순환**이어야 한다: 일몰에서 시작해 박명·별이 뜨는 밤을 지나 새벽으로 되돌아오는 하나의 긴 주기(수 분~십수 분, 실감1관 콘텐츠 8~12분 참조)와, 짧게 머물러도 완결감을 주는 짧은 주기(R-7 전반부)가 공존한다. 모든 변화는 점진적이며(R-17) 언제 입장해도 흐르는 중이어야 한다(MR-12). 소리는 빛의 시간과 함께 변한다(R-3) | MR-12, R-7, R-17, 조사 K §1.4·§1.5 |

### 3.5 구조·포지셔닝·측정 요구

| ID | 요구 | 근거 |
|---|---|---|
| R-23 | 멀티유저·소셜 기능 없음. 싱글 세션 + 정적 에셋 구조 | MR-16 — Hubs/Spatial 실패 교훈 |

## 4. 제약 조건

### 4.1 브라우저 구조적 제약 (설계로 흡수해야 하는 불변 조건 — 조사 E)

1. **자동 몰입 진입 불가**: 오디오 재생·Pointer Lock 모두 사용자 클릭 필수 → 입장 게이트(R-5)는 우회 불가능한 구조적 요구.
2. **Esc 해제 후 즉시 재진입 불가**: 새 클릭 필요 → Esc=일시정지 루프(R-6)로 흡수.
3. **모바일에서 Pointer Lock 미지원** → 데스크톱 전용(R-13).
4. **백그라운드 탭에서 렌더링은 정지, `<video>` 재생도 불안정. Web Audio만 지속** → "켜두기" 패턴은 오디오 중심으로 성립(R-7). 탭 복귀 시 시간 누적 오차 처리 필요.
5. **전체화면·Esc 가로채기(Keyboard Lock)는 브라우저별 지원 편차** → 권장 옵션(progressive enhancement)으로만.

### 4.2 프로젝트 제약

- 데스크톱 웹 우선, 모바일·VR 미지원 (GOAL Non-goals).
- 1인 관람 — 서버 상태·실시간 통신을 요구하는 구조 배제.
- 로컬 환경에서 개발·진행. 당분간 무료 운영.
- 콘텐츠는 무료(자유 라이선스) 소스 기반 — §3.4의 라이선스 정책 준수.

## 5. 제안 요청 항목

다음 단계에서 산출해야 할 제안의 목록과 각 제안의 요구 조건. **A(기술 스택)가 최우선이며 나머지 제안의 전제가 된다.**

### A. 기술 스택 제안 — 비교 조사 필수

> 현재 상태: 프로젝트 방향 논의에서 Three.js가 유력 후보로 거론되어 왔고 MRD 조사에서 실현 가능성이 확인되었으나, **대안과의 정식 비교는 수행된 적이 없다. 더 적합한 스택이 존재할 수 있으므로, 후보를 정식으로 비교 조사한 뒤 근거와 함께 선정할 것을 요구한다.**

**A-1. 조사 대상 (최소 범위)**

| 영역 | 비교 후보 (예시 — 조사에서 추가/제외 가능) |
|---|---|
| 3D 렌더링 | Three.js, Babylon.js, PlayCanvas, 웹 익스포트 게임 엔진(Godot/Unity 등), React Three Fiber 등 상위 레이어 |
| 공간 오디오 | Web Audio API PannerNode(HRTF) 직접 사용, 렌더링 엔진 내장 오디오, 앰비소닉 라이브러리(Omnitone 등) — 단 **백그라운드 재생 지속(R-7)이 가능한 Web Audio 계열이어야 함** |
| 영상 재생·전송 | 단일 MP4 프로그레시브, HLS/DASH 적응형(hls.js 등), 관리형 스트리밍 서비스 — **다중 해상도 적응(R-21)을 전제로 비교** |
| 애플리케이션 구조 | 순수 JS/TS + 번들러, 프레임워크(React/Svelte 등) 결합 여부 |

**A-2. 평가 기준 (제안서에 기준별 평가를 명시할 것)**

1. **몰입 품질 상한** — R-2(조작감)·R-4(웅장함)를 구현할 수 있는 렌더링·후처리 역량
2. **성능 하한** — R-10 정량 기준 충족 가능성, WebGL2/WebGPU 지원 경로
3. **공간 오디오 통합** — R-3 구현 난이도와 품질, 백그라운드 지속(R-7) 가능 여부
4. **비디오 텍스처 처리** — 고해상도 영상의 텍스처 업로드 경로 효율(내장 그래픽·Windows 환경이 최약 조건), 다중 해상도 적응 지원
5. **학습·개발 곡선** — 1인 개발 지속 가능성, 문서·커뮤니티·사례 풍부함
6. **번들 크기·로딩** — R-11 로딩 기준에 미치는 영향
7. **락인 리스크** — 상용 플랫폼 종속 여부(Spatial류 서비스형 도구 배제 근거 포함)

**A-3. 산출물**: 후보별 비교표 + 선정 스택 + 선정 근거 + 탈락 근거를 담은 기술 스택 제안서. 판단이 어려운 축은 소형 프로토타입으로 실측 검증할 것. **프로토타입은 최악 조건 조합(내장 그래픽 + Windows + 4K 비디오 텍스처)을 반드시 포함한다.**

### B. 경험 설계 제안

- **B-1. 공간 컨셉**: 일몰 콘텐츠를 감싸는 공간의 성격(전시관형/자연 통합형/추상형 등), 규모감을 만드는 방법(스케일 대비, 조명, 리드 라인).
- **B-2. 입장 연출 시나리오**: 게이트 화면 → 진입 동선 → 스크린 도달까지의 흐름. 실제 전시관의 입장 의식(어두운 복도, 소리의 점진적 등장 등)을 웹으로 옮기는 방식. **로딩 구간을 연출에 통합**(R-11)하고, 게이트에서 편안한 관람 설정(민감함/보통 프리셋)을 선택하게 하는 온보딩 검토.
- **B-3. 조작·카메라 사양**: 이동 속도, 입력 램프(≤80ms), 시야각(FOV), 충돌 처리 — R-2(v1.2 재정의)·R-14·R-15를 충족하는 구체 수치의 초안. **헤드밥은 기본 0.**
- **B-4. 상영 구조**: 일몰 콘텐츠의 루프형/상영형 여부와 그 이유 (GOAL 4.5: 콘텐츠를 따라감).
- **B-5. 일시정지·퇴장 설계**: Esc 일시정지 메뉴의 구성(설정·크레딧·퇴장), 관람 종료의 연출.

### C. 콘텐츠 파이프라인 제안

- **C-1. 소스 수급**: Pexels/Pixabay 등에서 일몰 4K 영상 후보 선정 기준(화질, 길이, 루프 적합성, 라이선스).
- **C-2. 가공**: 인코딩 사양(코덱, **다중 해상도 렌디션**, 비트레이트, 30fps 상한), 루프 이음새 처리.
- **C-3. 배포**: 정적 호스팅/CDN 구성과 영상 전송 방식 (A-1의 영상 전송 결정과 연동).
- **C-4. 라이선스 관리**: 소스별 출처·라이선스 기록 방식과 크레딧 페이지 형태 (R-22).

### D. 사운드 설계 제안

- **D-1. 사운드 레이어 구성**: 정위 음원(스크린/오브젝트 부착, 동시 4~8개 이내)과 배경 앰비언스(스테레오)의 역할 분담. **백그라운드 탭에서도 앰비언스가 지속되는 구조(R-7).**
- **D-2. 소스 수급**: Freesound 등에서 일몰·자연 앰비언트 소스 선정 기준.
- **D-3. 믹싱 방침**: 힐링 목적에 맞는 다이내믹스(급격한 소리 배제, R-17), 거리 감쇠 곡선, 마스터 볼륨 UX.

## 6. 제안 채택 기준

각 제안은 다음 순서의 우선순위로 평가·채택한다:

1. **요구 충족** — §3의 R-1~R-25를 충족하는가. 특히 R-2(조작감)·R-4(웅장함)·R-14(멀미 저감 기본값)는 타협 불가.
2. **1인 지속 가능성** — 혼자서 만들고 유지할 수 있는 복잡도인가.
3. **성능 실증** — 주장이 아니라 프로토타입 실측으로 R-10을 보였는가. 측정 조건(장비·해상도·시간)을 명시했는가.
4. **확장 여지** — MVP 범위를 벗어나지 않되, 향후 로드맵(§7)을 막지 않는 구조인가.
