# 소재 사양서 — 「일몰」 몰입 홀에 넣을 영상·파노라마 규격

> 소재를 **사거나 의뢰하거나 촬영할 때 상대에게 그대로 건네는 한 장.**
> 근거는 [조사 L](L-panorama-media-format.md), 규범은 [SRS-VID-9·10](../../srs/SRS.md).
> 작성 2026-09-11. 수치는 실행 중인 앱에서 조회한 실측 기하에서 계산했다 — 추정값에는 그렇게 표시한다.

---

## 0. 먼저: 이런 화면에 "국제 규격"이 있는가

**두 층위를 구분해야 한다. 한쪽만 표준이 있다.**

| 층위 | 표준 있나 | 내용 |
|---|---|---|
| **360 촬영 소재의 포맷** | ✅ **있다** | 에퀴렉탱귤러 2:1이 사실상 유일한 교환 포맷. 메타데이터는 Google **Spherical Video V2**(MP4의 `sv3d`/`st3d` 박스), MPEG **OMAF**(ISO/IEC 23090-2) |
| **띠형 파노라마 스크린의 화면 비율** | ❌ **없다** | 전시장마다 다르다. 국중박 실감1관 12:1, 우리 9.68:1. 표준이 있을 수 없다 — 건물이 다르므로 |

그래서 이 바닥에서 "규격"이라고 부르는 것은 국제 표준이 아니라 **전시장이 제작사에 건네는 사양서**다. 국중박 콘텐츠가 "공간에 특화된"이라 불리는 이유가 이것이고, **이 문서가 우리의 그 사양서**다.

**결론**: 스톡을 산다면 → §2(에퀴렉트, 표준 있음). 전용 제작을 맡긴다면 → §3(우리 벽면 좌표계, 이 문서가 규격).

## 1. 공간 (양쪽 경로 공통)

| 항목 | 값 |
|---|---|
| 홀 평면 | 타원 15m × 11m (반축), 둘레 82.2m |
| 스크린 | 벽면 **띠 하나**, 바닥에서 **0.2m ~ 8.2m** (높이 **8m**) |
| 펼친 길이 | **77.4m** — 입구를 제외한 전체 |
| 둘러싼 각도 | **339.1°** (입구 20.9° 제외) |
| 펼친 종횡비 | **9.68 : 1** |
| 관람 눈높이 | 1.65m |
| 벽까지 거리 | 11m(정면·배면) ~ 15m(좌우) |
| 수직 화각 | **38.3°** (최근접 벽 기준: 위 30.8° + 아래 7.5°) |
| 천장 | 9.4m (스크린 위는 무광 어두운 벽) |
| 바닥 | 광택 — 스크린을 반사한다 (소재 선택에 영향, §5) |

## 2. 경로 A — 360 스톡 소재를 살 때 (표준 있음)

### 2.1 필수 조건
- **투영**: 에퀴렉탱귤러(equirectangular). 큐브맵·EAC·피시아이는 변환 필요.
- **종횡비**: **가로가 세로의 정확히 2배.** 이것 하나만 확인하면 대부분 걸러진다.
- **모노(monoscopic)**: 스테레오(3D/VR) 소재는 두 눈 영상이 겹쳐 담겨 **2:1이 아니다** → 배제.
- **수평선이 세로 정중앙**에 있을 것 (에퀴렉트의 정의상 그러해야 하나, 후처리로 어긋난 파일이 있다).
- **VR180 배제** — 180°만 담아 339°를 채울 수 없다.

### 2.2 해상도 — 우리가 실제로 쓰는 건 세로의 21.3%뿐
밴드가 덮는 수직 화각이 38.3°이므로 에퀴렉트에서 **v = 0.329 ~ 0.542** 구간만 샘플링한다.

| 원본 | 실제 쓰는 띠 | 재생 픽셀 | 벽 밀도 | 판정 |
|---|---|---|---|---|
| 4K (3840×1920) | 3840×416 | 1.60 Mpix | 50 px/m · 11.3 px/deg | 부족 |
| 6K (5760×2880) | 5760×608 | 3.50 Mpix | 74 px/m · 17.0 px/deg | 최소선 |
| **8K (7680×3840)** | **7680×816** | **6.27 Mpix** | **99 px/m · 22.6 px/deg** | **권장** |

참고: 4K UHD(3840×2160)가 8.29 Mpix다. **밴드만 잘라내면 8K 360이 4K 일반 영상보다 가볍다.**

### 2.3 그 밖에
| 항목 | 요구 |
|---|---|
| 길이 | 20~60초. **끝과 처음이 이어질 것**(이음매 보이면 몇 분 관람에서 바로 티가 난다) |
| 내용 | **잔잔할 것** — 부서지는 파도·빠른 구름은 반복이 즉시 드러난다 |
| 오디오 | **불필요**(영상 트랙만). 프로젝트 규칙상 영상에 오디오 트랙 금지 |
| 라이선스 | 상업 이용 가능. `credits.json` 대장 등재 + SPDX 허용목록 통과 필요 |
| 색공간 | Rec.709 / sRGB. HDR(PQ·HLG)은 현재 파이프라인 미지원 |

## 3. 경로 B — 전용 제작을 의뢰할 때 (이 문서가 규격)

국중박 방식이다. 제작사는 구(球)가 아니라 **펼친 벽면에 직접** 그린다.

| 항목 | 값 |
|---|---|
| 캔버스 | **9.68 : 1**, 예: 7680 × 794 또는 5760 × 595 |
| 좌표계 | 가로 = 입구 오른쪽 가장자리부터 시계방향 **실제 호 길이**(0 → 77.4m) · 세로 = 바닥 0.2m(하단) → 8.2m(상단) |
| 이음 | 가로 좌우 끝은 **입구에서 만난다** — 이어질 필요 없음(입구가 가림) |
| 안전 영역 | 하단 1.5m는 벤치·관람자에 가릴 수 있음. 핵심 정보 배치 금지 |
| 주의 | **각도가 아니라 거리 기준**이다. 타원이라 좌우 벽은 관람자에게서 멀다(15m) — 그쪽 요소는 시각적으로 작아 보인다 |

전용 제작이면 §4.7의 기하 보정이 **불필요하다** — 애초에 이 벽에 맞춰 그리기 때문이다(조사 L §1.6).

## 4. 배급 인코딩 (우리가 처리 — 참고용)

| 항목 | 값 |
|---|---|
| 코덱 | **VP9 또는 AV1 필수** — H.264는 가로 4096px 상한이라 7680을 재생할 수 없다(AV1/VP9는 8192) |
| 전처리 | 에퀴렉트 원본에서 **v 0.329~0.542 구간만 크롭** 후 재인코딩. 앱에 `?vrange=0.329,0.542`로 알린다 |
| 프레임레이트 | 24~30fps 권장. 60fps는 디코드 비용만 2배이고 잔잔한 하늘·물에서는 이득이 거의 없다 |
| 루프 | `<video loop>` 금지 — A/B 스왑 로직이 소유(SRS-VID-2) |
| 비트레이트 | **미정** — M0a에서 실측해 정한다. 여기에 숫자를 지어내지 않는다 |

## 5. 소재 고를 때 실무 체크리스트

- [ ] 가로 = 세로 × 2 (정확히)
- [ ] 모노(스테레오 아님), VR180 아님, 에퀴렉트(큐브맵·피시아이 아님)
- [ ] 7680 이상 권장 (5760이 최소선)
- [ ] 20~60초, 끝↔처음이 이어짐
- [ ] 잔잔한 움직임 (부서지는 파도·빠른 구름 회피)
- [ ] 상업 이용 가능 라이선스, 출처 확인 가능
- [ ] **수평선 부근이 화질의 전부다** — 우리는 세로 21%만 쓴다. 하늘 꼭대기나 발밑이 아무리 좋아도 소용없고, **수평선 띠가 흐린 소재는 탈락**
- [ ] 바닥이 반사하므로 **아래쪽 21% 구간도 볼만할 것** (수면·모래는 좋고, 삼각대·촬영자가 찍힌 것은 나쁨)

## 6. 아직 확정하지 않은 것

- 비트레이트·총 용량 (M0a 실측 후)
- 디코드 + 반사 셰이더 동시 부하가 45fps(NFR-1)를 지키는지 (M0a)
- 유료 스톡의 실제 가격대 (미조사)
