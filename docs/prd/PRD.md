## 1. 개요

### 1.1 제품 한 문장

**어두운 대형 상영관을 직접 걸어 들어가, 벽면을 가득 채운 일몰과 공간을 감싸는 소리 속에서 원하는 만큼 머무는 웹 전시 — 링크 하나로 입장하는 힐링.**

### 1.2 범위

- 1호 콘텐츠 「일몰」을 완결된 경험으로 제공하는 데스크톱 웹 MVP. 게이트 → 입장 연출(복도) → 상영관 관람 → 일시정지/퇴장의 전 흐름.
- 제외: 콘텐츠 확장 체계, 다중 전시실, 모바일, VR, 동시 관람, 수익화 (RFP §1.2).

### 1.3 확정된 경험 설계 (사용자 결정, 2026-08-22)

| 항목 | 결정 |
|---|---|
| 공간 컨셉 | **실내 대형 상영관형** — 국중박 실감영상관의 원체험을 따르는, 어둠 속 압도적 스케일의 실내 공간 + 대형 스크린 |
| 입장 연출 | **어두운 복도를 직접 걸어서 입장** — 게이트 클릭 후 어둠에서 시작, 소리가 먼저 들리고, 복도를 걸어 상영관에 도달. 조작 튜토리얼 구간 겸함. 스킵 가능 |
| 상영 구조 | **루프형** — 시작·끝 없이 일몰이 계속 흐름. 아무 때나 입장해도 흐르는 중 |

### 1.4 용어

- **게이트(Gate)**: 입장 전 화면. "입장하기" 클릭이 오디오·시점 잠금을 해제하는 브라우저 요구를 겸함.
- **복도(Corridor)**: 게이트와 상영관 사이의 입장 연출 공간.
- **상영관(Hall)**: 일몰이 상영되는 본 공간.
- **정위 음원**: HRTF 패닝으로 방향·거리를 갖는 음원. **앰비언스**: 방향 없는 스테레오 배경음.
- **하한 장비**: 외장 GPU 없는 내장 그래픽(Intel Iris Xe급) 노트북 — 모든 성능 기준의 측정 기준기.

## 2. 제품 정의

### 2.1 타깃 (MRD §3)

1차: S1 번아웃 직장인(즉시 켜서 쉬기), S2 힐링 콘텐츠 헤비 유저(켜두기), S3 2030 전시 애호가(작품 감상 프레이밍). 여성 비중이 높은 타깃 특성상 멀미 감수성(약 2배)을 기본값 설계에 반영한다.

### 2.2 핵심 사용자 여정

```
[발견] 링크 클릭
  → [게이트] 로딩과 함께 작품 소개 + 헤드폰 안내 + (선택) 편안한 관람 설정
     "입장하기" 클릭 = 오디오 시작 + 시점 잠금
  → [복도] 어둠 속에서 눈이 뜨임. 멀리서 앰비언스가 들림.
     WASD/방향키로 복도를 걸음 (= 조작 습득). 걸을수록 소리가 가까워짐. [스킵 가능]
  → [상영관] 복도 끝, 공간이 열리며 대형 스크린의 일몰이 시야를 채움.
     자유 관람: 다가가기/물러서기/앉을 위치 찾기. 소리는 위치 따라 변함.
     원하는 만큼 머묾 (2~3분에도 완결감, 몇십 분도 가능. 탭 전환 시 소리는 지속)
  → [일시정지] Esc → 반투명 메뉴 (계속 / 설정 / 크레딧 / 나가기)
  → [퇴장] 페이드 아웃 + 크레딧
```

### 2.3 성공의 정의 (MVP)

정량 성공 기준은 GOAL에 따라 의도적 보류. MVP의 게이트 조건은: ① §5 성능 기준 실측 충족, ② 외부 관람자 1인 이상이 멀미·불편 없이 관람 완료, ③ M3 QA 체크리스트(§8) 통과.

## 3. 기술 스택 (잠정 확정 — M0 실측 통과 조건부)

> 근거는 [조사 H](research/H-rendering-stack.md)·[I](research/I-video-delivery-hosting.md)·[J](research/J-audio-app-architecture.md). RFP §5.A의 7개 기준으로 5개 후보(Three.js/Babylon.js/PlayCanvas/Godot 웹/Unity Web)를 정식 비교한 결과다.

| 영역 | 결정 | 핵심 근거 | 탈락 후보 요약 |
|---|---|---|---|
| 3D 렌더링 | **Three.js r185 계열 (버전 핀 고정) + WebGLRenderer(WebGL2)** | 유일하게 HRTF 기본값(소스 확인), 런타임 최박형 → 45fps 하한에 최유리, gzip 182KB 의존성 0, 커뮤니티 압도적(npm 월 5,730만, 포럼 30일 활성 1,019명) | Babylon 9.x = 근소 2순위(§9 V13 재평가 트리거 유지). PlayCanvas = HRTF 미노출·번들 3.2배. Godot 웹 = 영상 Theora 전용(4K 불가)으로 기능 부적합. Unity Web = 웹 오디오 스페이셜라이저 미지원으로 기능 부적합 |
| 후처리 | **pmndrs/postprocessing** (Zlib) | 단일 패스 머지, SelectiveBloom(스크린만), LUT 색보정, ACES 톤매핑, SMAA | 코어 EffectComposer 대비 오버헤드 낮음 |
| 공간 오디오 | **Three.js PositionalAudio + 자체 GainNode 믹서** (하이브리드) | HRTF·씬 동기화는 three가 해결, 믹싱·크로스페이드는 Web Audio 직접 제어. `distanceModel`은 `'linear'`로 명시 변경(기본 inverse는 음량이 0에 도달하지 않아 음원 누적) | Howler(3D 동기화 자작+유지보수 정체), Resonance/Omnitone(2026-04 아카이브) |
| 영상 전송 | **프로그레시브 MP4 렌디션 4종 + 로드 시 1회 적응 선택** | 단일 영상 무한 루프 + WebGL 텍스처 = HLS의 최약점(루프 버그, iOS 텍스처 이력)에 정확히 해당. ABR의 이득 없음 | HLS/DASH(복잡도·루프 리스크), 관리형(뷰당 과금·락인) |
| 호스팅 | **Cloudflare Pages(사이트) + R2 커스텀 도메인(영상·에셋·오디오)** | 에그레스 무료 → 월 비용 ~$0, 뷰 증가에도 불변. 약관상 R2는 CDN 영상 제한의 명시적 예외. r2.dev 금지, immutable 캐시 + CORS 필수 | Vercel/Netlify/GitHub Pages(대역폭·용량 한도로 영상 불가) |
| 앱 구조 | **순수 TypeScript + Vite** (React/R3F 미도입) | DOM UI 3개뿐, 명령형 루프 중심 구조에 선언적 레이어 이점 없음, +97KB 회피 | R3F(React 도입 근거 부재) |
| 분석 | **미정 — 공개 시점 결정** (후보: Umami Cloud 무료 티어 우선 / 셀프호스팅은 서버 상시 운영이 필요해 "무료·정적" 방침과 충돌하므로 비권고). 이벤트 훅만 M2에 no-op으로 심음 | 감사 A2에서 셀프호스팅 확정이 반박됨 (v1.1) | — |

**배포 시점 (v1.1)**: 개발·검증은 **로컬 우선**. 클라우드 배포(Pages·R2)·도메인 취득·전송 실측은 배포 준비 단계(M3 전)로 이월한다 — 스택으로서의 Pages+R2 선택은 유지하되 실행만 미룬다.
**한국 레이턴시 리스크**: Cloudflare 무료 플랜의 서울 PoP 미라우팅은 **확인된 커뮤니티 리포트**(KT→LAX, 요청당 +500ms~3s — [추정]에서 격상, 감사 A2). 여기에 무료 플랜 **CDN 캐시 상한 512MB**가 겹치면 대형 파일은 캐시 우회로 매번 원본 전송된다 → 렌디션 파일 ≤400MB 제약(§6.1)의 근거. 배포 준비 단계에서 한국발 TTFB/처리량 실측(이월된 V14) 후 필요 시 영상만 Bunny CDN(서울 PoP, $0.03/GB)으로 분리.

## 4. 기능 요구사항 (FR)

RFP 요구(R-x)와의 대응을 병기. **[M0]** 표시는 프로토타입 실측 결과에 따라 수치가 조정될 수 있는 항목.

### 4.1 게이트 (FR-1x)

- **FR-10** 첫 화면(게이트)은 2.5초 이내 표시된다. 구성: 작품 제목·한 줄 소개, **헤드폰 권장 안내(아이콘+문구)**, **광과민성·멀미 사전 고지 1줄**(v1.1 — QA 항목의 근거 요구로 승격), "입장하기" 버튼, 설정 열기, 크레딧 링크. 문구는 FR-90 표현 제약 준수. (R-5, R-11)
- **FR-11** "입장하기" 클릭 한 번으로 `AudioContext.resume()` + Pointer Lock 요청 + (선택) 전체화면 제안을 처리한다. 전체화면은 권장 옵션이며 거부해도 경험은 성립한다. (R-5, §4.1 제약)
- **FR-12** 로딩이 3초를 넘으면 실측 퍼센트 진행률을 표시한다. 로딩 중에도 게이트의 정보·설정은 조작 가능하다. 에셋 로딩은 게이트 표시와 병행하며, 복도 진입에 필요한 최소 에셋만 로딩 완료되면 입장 가능(상영관 고품질 에셋은 백그라운드 스트리밍). (R-11)
- **FR-13** 게이트에서 "편안한 관람" 온보딩을 제공한다: **민감함/보통** 2택 프리셋(민감함 = 저감 프로필 §4.5). OS `prefers-reduced-motion: reduce` 감지 시 "민감함"을 기본 선택하고 알림·해제 UI를 노출한다. (R-16)
- **FR-14** WebGL2 미지원·모바일 접속 시 게이트 대신 안내 화면을 표시한다(데스크톱 브라우저 안내, 대표 이미지 1장). (R-13)

### 4.2 복도 — 입장 연출 (FR-2x)

- **FR-20** 입장 직후 짧은 암전에서 페이드 인(0.5초 이상 점진, R-17). 시야는 어두운 복도. 상영관 방향에 배치된 **유도 정위 음원**이 목적지를 안내한다(방향 없는 앰비언스와는 별개 레이어 — v1.1 용어 정정).
- **FR-21** 복도는 조작 튜토리얼을 겸한다: 이동(WASD/방향키)·시점(마우스) 안내를 화면 하단에 최소한으로 표시하고, 실제 이동이 감지되면 사라진다. 안내 문구의 키 표기는 사용자 키보드 각인과 불일치할 수 있음을 감안해 아이콘 병기. (R-1)
- **FR-22** 복도 길이는 도보 20~40초 수준 [M0에서 체감 튜닝]. 걷는 동안 소리가 점점 가까워지고 벽면 빛이 점차 변해 기대감을 조성한다.
- **FR-23** **스킵 가능**: 복도 어디서든 스킵 조작(화면 표시)으로 상영관 입구로 즉시 이동(페이드 전환). 재방문자(localStorage 방문 기록)에게는 게이트에서 "바로 상영관 입장" 옵션 제공. (R-18)
- **FR-24** 복도 → 상영관 진입은 공간이 열리는 연출로 처리하되 급격한 밝기 변화 금지 — 상영관의 빛이 점진적으로 시야를 채운다. (R-17)

### 4.3 상영관 — 관람 (FR-3x)

- **FR-30** 상영관은 압도적 스케일의 실내 공간이다: 첫 시야에서 규모감이 전달되어야 하며(R-4), 스크린은 시야를 채우는 대형(관람자 신장 대비 수 배). 공간 연출(스케일 대비·조명·리드 라인)의 구체 수치는 M1 아트 패스에서 확정.
- **FR-31** 이동: WASD/방향키 + 마우스 시점(Pointer Lock). 등속 이동 기본(가속 없음) — 단 "부드러움"은 **짧은 입력 램프(≤80ms) + 마우스 원델타 직결 + 프레임타임 일관성**으로 확보(R-2 v1.2 재정의). 충돌 처리(벽·스크린 통과 불가, 끼임 없음), 이동 범위는 관람 영역으로 제한. (R-1, R-2(재정의), R-14)
- **FR-32** 키 입력은 물리 키 위치(`KeyboardEvent.code`) 기준. `isComposing`/keyCode 229 가드로 한글 IME 상태에서도 정상 동작. (R-1)
- **FR-33** 일몰 영상은 스크린에 **끊김 없는 루프**로 상영된다: 루프-세이프 마스터(끝 1초를 앞 1초와 사전 크로스페이드) + 이중 `<video>` A/B 스왑 + `requestVideoFrameCallback` 트리거 + 셰이더 크로스페이드(0.2~0.5초)의 조합. 영상에는 오디오 트랙이 없다(분리 원칙 §6.3). (조사 I §5)
- **FR-34** 비디오 텍스처 갱신은 rVFC로 영상 fps에 게이팅한다(렌더 fps 업로드 금지). 동시 활성 비디오 텍스처는 스왑 순간을 제외하고 1개. (R-20, 조사 H V3)
- **FR-35** 스크린 발광 연출: 에미시브 + SelectiveBloom(스크린만) + 영상 평균색을 샘플링해 구동하는 소수의 동적 라이트로 공간 스필 라이트를 근사한다. RectAreaLight 실사용은 하지 않는다(그림자·텍스처 미지원). [M0 V5/V7에서 비용 검증]
- **FR-36** 관람에는 목표·진행·UI가 없다. HUD는 기본 비표시. (GOAL — 목표 없는 감상)
- **FR-37** (SHOULD, v1.1 신설) 상영관 도달 후 **2분 이내에 감상 사이클이 최소 1회 완결**되도록 영상 루프 길이와 사운드 레이어 순환 주기를 설계한다 — "짧게 머물러도 완결감"(R-7 전반부)의 구현. 복도(20~40초)+로딩이 세션의 과반을 차지하지 않게 재방문 직행 경로(FR-23)와 함께 고려. (MR-12, R-7)
- **FR-90** (MUST, v1.1 신설 — 감사에서 소실 복원) **표현 제약**: 제품의 모든 문구(게이트·크레딧·소개·공개 채널)는 "웹을 위해 창작된 원본 전시"로 프레이밍하고, 의학적 치료·치유 효능을 주장하지 않는다 — '이완'·'휴식' 수준의 표현만 사용. (MR-15, R-24)

### 4.4 사운드 (FR-4x)

- **FR-40** 구성: 스테레오 앰비언스 베이스 1 + 보조 레이어 2~3(서로 다른 길이 30~90초 루프를 다른 오프셋으로 동시 재생 — 반복 비지각화) + **정위 음원 4~8개(전부 모노)** 를 스크린·공간 요소에 배치. (R-3, 조사 J)
- **FR-41** 전 소스는 OGG Vorbis/Opus의 `AudioBufferSourceNode` 루프(샘플 정확). MP3·MediaElementSource 금지. 5분급 통짜 버퍼 금지(메모리). (조사 J)
- **FR-42** 거리 감쇠: `distanceModel = 'linear'` 명시, maxDistance는 관람 영역 최대 도달 거리보다 크게. 정위 음원은 켜둔 채 gain으로 무음화(start/stop 반복 금지 — Chrome 성능 이슈 #15422 회피). (조사 J)
- **FR-43** 모든 음량 변화는 크로스페이드(클릭 노이즈 금지): `linearRampToValueAtTime` 이상, 등파워 필요 시 커브 스케줄. 씬 전이(복도↔상영관, 일시정지)의 믹스 전환은 상태 머신 onEnter/onExit에서 트리거. (R-17)
- **FR-44** **백그라운드 재생**: 탭이 숨겨져도 앰비언스는 지속된다. `visibilitychange → suspend()` 코드를 넣지 않는다(널리 퍼진 안티패턴). 오디오 스케줄링은 전부 `ctx.currentTime` 기준(rAF 의존 금지). 탭 복귀 시 rAF 델타 클램핑(최대 0.1초)으로 카메라 순간이동 방지. (R-7, 조사 E·J)
- **FR-45** 마스터 볼륨·음소거는 상시 접근 가능(일시정지 메뉴 + 단축키 M). `ctx.onstatechange`에서 running이 아니면 resume 재시도. (R-17)

### 4.5 설정·편안함 (FR-5x)

- **FR-50** 설정 패널은 게이트·일시정지 메뉴 양쪽에서 접근 가능. (R-15)
- **FR-51** 항목과 기본값:

|---|---|---|
| FOV | 60~100° 슬라이더 | **90°** + "낮을수록 멀미 완화" 안내 |
| 이동 속도 | 3단(느림/보통/빠름) | 보통 |
| 마우스 감도 | 수평/수직 분리 슬라이더 | 중간 |

| 헤드밥 | 슬라이더 | **0** |

| 마우스 스무딩 | 토글 | **꺼짐** |

### 4.6 일시정지·퇴장 (FR-6x)

- **FR-60** Esc = 일시정지: 시점 잠금 해제와 동시에 반투명 오버레이 메뉴 표시(계속 / 설정 / 크레딧 / 나가기). "계속" 클릭으로 복귀(Esc 직후 즉시 재잠금은 브라우저가 막으므로 버튼은 약 1.5초 후 활성화). (R-6)
- **FR-61** 일시정지는 별도 씬 상태가 아니라 직전 상태를 기억하는 오버레이로 구현. 일시정지 중 렌더는 지속(배경이 흐림 처리), 오디오는 볼륨을 낮춘 채 지속 [연출 판단, M1에서 확정].
- **FR-62** 크레딧: 영상·사운드 소스별 출처·라이선스 표기(CC-BY 요구 형식 준수), 프로젝트 소개. 게이트와 일시정지 메뉴에서 접근. (R-22)
- **FR-63** 나가기: 페이드 아웃 → 크레딧 화면. 재입장 버튼 제공.

### 4.7 씬 상태 관리 (FR-7x)

- **FR-70** 상태 머신: `gate → corridor → hall`, `paused`는 오버레이(previous 기억). 전이는 union 타입 + 전이 테이블(XState 미도입 — 4상태 규모). 각 상태 onEnter/onExit에서 오디오 믹스·페이드 트리거. (조사 J)
- **FR-71** 아키텍처: `scene/`(three, store 구독만) · `audio/`(오디오 클럭 스케줄러) · `ui/`(DOM 오버레이, store 발행) · `core/`(store·settings·상태 머신). 단일 방향 규칙 — UI는 write, 3D는 read, 상호 직접 참조 금지. DOM UI는 canvas 위 오버레이(`pointer-events` 토글), WebGL 내 UI 렌더링 금지.

### 4.8 분석 (FR-8x, SHOULD)

- **FR-80** (v1.1 개정) 쿠키·개인 식별 없는 익명 분석. **도구는 미정 — 공개 시점에 결정**(우선 후보: Umami Cloud 무료 티어. 셀프호스팅은 상시 서버가 필요해 무료·정적 방침과 충돌하므로 비권고 — 감사 D2). 수집 화이트리스트(이 목록 밖 수집 금지): 로딩 완료(소요 초), 입장(재방문 여부), 복도 스킵, 상영관 도달, 체류 시간 구간, 이탈 지점, 적용 품질 프리셋·렌더 스케일·렌디션·평균 fps(성능 검증용), 오류 종류. **접근성 설정 사용 여부(comfort)는 준민감 정보로 수집하지 않는다.** 동의 배너 불필요 구성. 화이트리스트와 서버/CDN 로그 IP 정책(마스킹 또는 단기 파기)을 크레딧/정책 페이지에 명시. (R-25)
- **FR-81** MVP 우선순위: 분석은 M3(공개) 시점 도입. 이벤트 훅 포인트만 M2에서 no-op으로 심어둔다.

> **판정 단서 (v1.1 — R-10의 완화 조항 복원)**: NFR-1~3은 자동 품질 저하(프리셋·렌더 스케일)가 개입한 상태로 충족해도 합격으로 인정하되, 판정 시 적용된 프리셋과 렌더 스케일 로그를 첨부한다.

- **NFR-10 품질 프리셋**: Low/Med/High 3단(차이: 그림자 해상도, 후처리 체인, 파티클, 렌더 스케일 범위, 영상 렌디션 상한)을 표로 문서화. 초기 자동 감지(detect-gpu 또는 동등) — **미판정 GPU는 Low에서 시작 후 런타임 상향**. 렌더 스케일 0.6~1.5 범위 내 자동 조정 + 히스테리시스(프리셋 핑퐁 금지). 프리셋별 실제 범위·DPR 상한과 **유효 픽셀 공식(= viewport × min(devicePixelRatio, DPR상한) × renderScale)** 은 SRS §8.1이 정의하며 총 유효 픽셀이 하한 장비 예산을 넘지 않게 상호 제약한다(v1.1). 수동 오버라이드는 localStorage 보존. (R-12)
- **NFR-11 디버그 오버레이**: URL 파라미터로 fps/프리셋/렌더 스케일/드로우콜 표시 — QA 검증 수단.
- **NFR-12 컨텍스트 손실**: `webglcontextlost` 처리(재입장 안내), WebGL2 미지원 안내. (R-13)

## 6. 콘텐츠 명세

### 6.1 일몰 영상 (R-19·R-21)

- **소스**: Pexels/Pixabay 무료 라이선스 4K 일몰 실사 영상. 선정 기준: ① 3~5분 또는 루프 적합 구간 보유, ② 고정 카메라(흔들림 없음 — 멀미·안정화 근거), ③ 하늘 그라데이션 계조가 풍부하고 밴딩 없는 원본, ④ 라이선스 조건 확인(원본 재배포 금지 조항 대응 — 3D 공간 통합 상영), ⑤ 수평선·태양 위치가 대형 스크린 구도에 맞을 것, **⑥ (v1.1 — 루프형 결정과의 물리 충돌 방지) 루프 구간 내 태양 위치·고도 변화가 지각 임계 이하일 것 — 또는 태양이 이미 수평선 아래인 잔광(afterglow) 구간을 채택**. 태양은 단조 하강하므로 크로스페이드는 밝기 계단은 숨겨도 위치 점프는 못 숨긴다(감사 A2). 최종 채택 전 후보 3개 이상으로 루프 지각 테스트(M0a V16).
- **마스터 가공**: 끝 1초를 앞 1초와 크로스페이드한 **루프-세이프 마스터** 생성. 총 프레임을 GOP 배수(2초 GOP)로 트림. 밴딩 발생 시 미세 디더.
- **렌디션** (v1.1 — **3종 체계, 2160p 삭제**·감사 D3 결정 / H.264 단일 코덱, CRF 19 + VBV, 30fps CFR, yuv420p, bt709, faststart, **-an 오디오 제거**):

| 렌디션 | Level | 목표/maxrate |
|---|---|---|
| 1440p | 5.0 | 9M/12M — 고사양 기본 |
| 1080p | 4.0 | 5.5M/7M — **하한 장비 기본** |
| 720p | 3.1 | 3M/4M — 저대역폭 폴백 |

- **파일 크기 하드 제약 (v1.1)**: 렌디션 각 파일 **≤ 400MB** — Cloudflare 무료 플랜 CDN 캐시 상한(512MB)의 안전 마진. 이 제약이 마스터 길이를 구속한다(1440p 9Mbps 기준 약 5.9분 상한).
- **렌디션 선택**: 로드 시 1회 — 3D 스크린의 화면상 픽셀 폭 기준(임계는 SRS-VID-1이 실제 뷰포트 기준으로 정의 — 1080p 모니터에서 1440p 도달 가능해야 함, 감사 F-5 정정) + deviceMemory/downlink 힌트. 이후 전환 없음(품질 프리셋 수동 변경 시에만 재로드).
- AV1/HEVC 렌디션은 MVP 도입 안 함 — 단, 트래픽 과금 CDN(Bunny 등)으로 전환하는 경우 1080p 이하에 한해 재검토(v1.1 조건 부기, MR-18 추적).

### 6.2 사운드 (R-22)

- **소스**: Freesound(CC0 우선, CC-BY 허용, **CC-BY-NC 배제**) + Pixabay SFX. 라이선스 필드와 설명란 모두 확인.
- **구성**: 해변/바람/새 등 일몰 정경의 앰비언스 베이스(스테레오 30~90초) + 보조 레이어 2~3(서로 다른 길이) + 정위 음원 4~8(모노: 파도 방향, 바람 스팟, 공간 톤 등 — 사운드 디자인은 M1 확정).
- **포맷**: OGG Vorbis 또는 Opus, 제로 크로싱 트림, 배포 전 루프 청취 검수.
- **라이선스 대장**: 소스별 URL·저작자·라이선스·사용 위치를 기록하는 `CREDITS` 데이터 파일 → 크레딧 화면과 동기화. (R-22)

### 6.3 오디오·영상 분리 원칙

영상 파일에 오디오를 넣지 않는다(AAC 프라이밍 갭 → 루프 파괴). 일몰의 소리는 전부 §6.2의 Web Audio 레이어로 구성 — 이 분리가 백그라운드 재생(FR-44)과 샘플 정확 루프(FR-41)를 동시에 가능하게 한다.

### 6.4 3D 에셋

- 상영관·복도 모델: glTF/GLB + Draco(또는 Meshopt), 텍스처 KTX2/Basis. 조명은 베이크 라이트맵 우선 + 실시간 최소화 [M0 V7 확정].
- 전 에셋 R2 배포, immutable 캐시, CORS 헤더, 압축 포맷 이중 압축 금지.
