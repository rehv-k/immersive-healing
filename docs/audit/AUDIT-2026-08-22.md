## 1. 질문별 종합 판정

### Q1. 최종 기술 스택은 무엇이며, 최선의 선택인가?

**스택: Three.js r185(WebGL2) + pmndrs/postprocessing / PositionalAudio+자체 GainNode / 프로그레시브 MP4 / Cloudflare Pages+R2 / 순수 TS+Vite.**

**판정: 핵심 결정 6개 중 5개 생존 — 스택 교체 불필요. 단 1건은 변경 필요.**

- 가장 강력한 대안 2개가 반박에 실패했다: **WebGPU-first**(Firefox가 여전히 기본 비활성 — 필수 브라우저가 항상 폴백으로 떨어짐), **실시간 렌더링 하늘**(절차적 포토리얼의 1인 노동량이 영상 파이프라인 전체보다 큼 + "상영관에서 영상을 본다"는 컨셉 정합).
- 탈락 판정(Godot 웹 = Theora 전용으로 4K 불가, Unity 웹 = 스페이셜라이저 미지원)은 최신 공식 문서로 재확인 — **유효**.
- **변경 필요 1건: Umami 셀프호스팅 → 철회.** 상시 서버+DB가 필요해 "무료 운영"과 "서버 없는 정적 구조"(MR-16) 방침과 정면 충돌. **Umami Cloud 무료 티어(월 10만 이벤트)로 변경 권고.**
- **결정은 옳았으나 근거가 낡은 것 3건**: HLS 배제 근거로 인용한 hls.js 버그 2건은 이미 종결됨(진짜 근거는 "ABR 무익 + A/B 스왑과 MSE의 구조적 충돌"로 교체 필요), three.js #15422도 종결(수정이 이미 upstream — SRS의 가드 요구는 중복), r185 핀 고정의 실제 이유는 postprocessing의 `<0.186.0` peer 상한(자율적 선택이 아니라 종속 — 정직하게 명문화 필요).
- **미발견이었던 중대 제약 1건: Cloudflare 무료 플랜의 CDN 캐시 상한 512MB.** 2160p 렌디션(480MB)이 상한의 94%이고 5분 소스면 초과 → 캐시 불가 → 한국 레이턴시 완화 수단 소실. **2160p 삭제(3렌디션 체계) + "렌디션 파일 ≤400MB" 하드 제약** 권고.
- **루프형 결정과 일몰 타임랩스의 물리적 긴장**: 태양은 단조 하강하므로 루프 시 위치 점프. 소스 선정 기준에 "루프 구간 태양 이동 지각 임계 이하(또는 태양이 수평선 아래인 잔광 구간)" 추가 필요 — 소스 선정을 규정하므로 M0로 미루면 재인코딩 비용.

### Q2. 시스템 아키텍처는 역할별로 잘 분리되었는가?

**판정: 방향은 옳으나 현 명세로는 불성립 — 구현 차단급 11건.** 대표 3건:

1. **`paused` 전이의 소유자가 없다.** "ui는 write, scene은 read" 규칙과 "Pointer Lock 해제 감지가 유일한 진입 경로" 규칙이 서로를 막아 어떤 구현도 규칙 준수가 불가능(자기모순). → core에 입력 세션 소유자(`input-session`) 신설 필요.
2. **탭 전환이 Pointer Lock을 해제한다** → 탭을 바꿀 때마다 일시정지+볼륨 35%가 발동해 **"켜두는 힐링"(MR-12) 핵심 가치가 설계상 깨진다.** visibilityState로 분기하는 규칙 필요.
3. **오류를 UI에 전달할 채널이 상태 트리에 없다** → 오류표 7건 중 5건이 구현 불가. `sys.notices` 채널 + 재시도 액션 신설 필요.

그 외 차단급: `unsupported`가 상태 타입에 없어 컴파일 실패, three.js AudioListener와 자체 버스의 배선·AudioContext 소유권 미명세(방치 시 InvalidAccessError로 100% 막힘), 볼륨 3중 소스(마스터×일시정지×음소거)의 결합 공식 부재, 복도→상영관 "도달" 판정·스폰 지점 미정의(GLB 명명 규약 필요), A/B 스왑 중 일시정지/탭 전환 미정의, 매니페스트가 영상 렌디션·폴백 에셋을 표현 불가, `comfortProfile` boolean이 3상태(민감함/보통/custom)를 표현 불가 등.

**반면 15개 항목은 "검사했으나 이상 없음"** — 오디오 페이드 API, 백그라운드 정책, 다층 루프, 인코딩 프로파일, `code` 기반 입력, 델타 클램프, 톤매핑 파이프라인, localStorage 방어 등 조사 기반 결정들은 견고하다.

### Q3. 각 문서에 빠진 것은 없고 서로 sync가 맞는가?

**판정: 골격은 견고하나 정합 결함 다수 — 치명 5 / 중대 14 / 경미 20.** 치명 5건:

1. **MR-15(MUST)/R-24 완전 소실** — "웹을 위해 창작된 원본 전시, 의학적 효능 주장 금지"가 PRD·SRS에 0건. 게이트·크레딧 문구가 지켜야 할 표현 제약이 명세에 없음. 추적성 매트릭스에서도 R-24 행만 누락.
2. **"관성 vs 등속" 무기록 충돌** — RFP가 "타협 불가"로 지정한 R-2(관성)와 R-14(등속)가 배타적인데 조정 기록 없이 PRD가 등속만 채택, 심지어 FR-31이 R-2를 인용하며 정반대를 명세.
3. **M0 완료 조건(R-10: 1% low·스파이크 포함) 판정 절차가 M0 계획에 없음** — 게이트인데 게이트 판정 항목이 없다.
4. **적응 임계 40 vs 목표 45** — fps 40~45 구간에서 시스템이 "정상 동작"하며 NFR-1을 지속 위반하는 안정 평형.
5. **렌디션 선택 임계(pw>2200)가 1080p 모니터에서 도달 불가** — "고사양 기본 1440p"가 4K 모니터 전용이 되는 산술 오류.

중대급: 추적성 매트릭스의 허위 매핑 다수(R-8·R-9 대응 부재 등), 로딩 NFR-5~7이 SRS에 미반영, FR-22(복도 길이)·FR-36(HUD 없음) 소실, MR-18(듀얼 코덱) 무기록 소실, "2~3분 완결감"(R-7 전반부) 미구현, 키보드 단독 관람의 수직 회전 수단 부재(WCAG 2.1.1), 분석 수집 항목이 화이트리스트 초과(특히 `comfort`는 접근성 필요를 시사하는 준민감 정보), R-4(웅장함, 타협 불가)에 검증 방법 전무, PRD 미해결 "일몰 소스 선정"이 SRS에서 증발, CC-BY-NC 빌드 검출이 타입상 도달 불가 등.

**이상 없음 확인**: 내부 링크 24개 전수 무결, GOAL Non-goals 6항 전 문서 준수, 렌디션·FOV·페이드 시간·설정 기본값·정위 음원 수 등 핵심 수치 다수는 완전 일치.

### Q4. 조사는 충분했고 그에 따른 결정인가?

**판정: 방법론은 견고(소스 코드 직접 확인, 약관·요금 원문, API 실측 수치) — 그러나 공백 7건.**

- 미조사: ① 이중 `<video>` 동일 src의 HTTP 캐시 공유 여부(A/B 스왑 설계의 전제 — 미공유면 전송량·메모리 2배), ② 총 **메모리 예산표** 부재(오디오 ~120MB + 디코더 2개 + 텍스처가 통합 그래픽의 공유 RAM에 동시 상주), ③ **웹폰트 정책**(한글 폰트는 서브셋 없이 수 MB — 단독으로 LCP 2.5초를 깰 수 있음), ④ **Firefox 측정 수단**(필수 브라우저인데 M0 절차가 전부 Chrome 도구 전제), ⑤ Safari 지원 결정 유예의 위험, ⑥ 512MB 캐시 상한(발견됨), ⑦ 루프-태양 모순(발견됨).
- 한국 레이턴시는 문서가 `[추정]`으로 약하게 적었으나 실제로는 확인된 커뮤니티 리포트(KT→LAX 라우팅, +500ms~3s) — **V14를 M0 최우선으로 승격** 필요.

### Q5. 개발 전 과정은 모두 끝났는가?

**판정: 반박됨 — 단, 문서 부족이 아니라 물리적 전제조건의 공백.**

- **최중대: 하한 기준기가 존재할 수 없는 PC.** 실측 결과 개발 PC는 **GTX 1650(외장) + i3-9100F(F = 내장 그래픽 미탑재)**. 문서 전체의 성능 기준기인 "내장 그래픽(Iris Xe급) 노트북"을 근사할 수단조차 없어 M0 검증 V1·V2·V6·V10 등 최소 6개가 실행 불가. 특히 **최대 기술 리스크(V1 비디오 텍스처 업로드)가 정확히 프록시 불가능한 항목.** 방치 시 "기준 미달 → 무언의 기준 완화"가 결정 없이 일어난다. → **(a) Iris Xe급 중고 노트북 확보, (b) M0를 M0a(현 PC에서 가능한 상대·기능 검증)/M0b(기준기 필수 절대 판정)로 분할, (c) 하한 정의 변경(MRD까지 소급)** 중 택1 결정 필요. 권고는 (b)+필요 시 (a).
- **순서 모순**: 도메인이 "M3 전 확정"인데 M0 검증 V9·V14가 커스텀 도메인을 전제(r2.dev는 레이트 리밋으로 측정 왜곡). **테스트 도메인 취득은 M0 전 항목** — 연 1~2만 원의 실비이며 "무료 운영"과 충돌하는 유일한 비용인데 어디에도 언급 없음.
- **M0 준비물 개념 부재**: FFmpeg 미설치, Firefox 미설치, 일몰 영상·사운드 소스 미확보, wrangler·Cloudflare 계정 미준비. (Node/git/VS Code는 확인됨)
- **최대 리스크의 절차 부재**: 기술 리스크에는 검증 14개, **최대 리스크(연출 품질, MRD 심각도 '높음')에는 0개.** 아트 디렉션 절차·3D 에셋 제작 주체 결정·검수 기준이 어느 문서에도 없음. M0와 병행 착수 필요.
- **저장소·규칙 부재**: git 미초기화(문서 1,300줄+조사 10건이 버전관리 없이 존재), 코드 라이선스 미결정(코드/에셋 라이선스 분리 필요), CLAUDE.md 부재(흩어진 금지 규칙 — setVolume 금지, MP3 금지 등 — 을 AI 협업 시 매번 위반하게 됨), M0 종합 실패 시 희생 우선순위 규칙 부재("타협 불가" 3항목이 동시 성립 불가할 때의 교착).
- **과잉 관료화 배제 확인**: 별도 SDD/TC/용어집/리스크 대장/CI/백업 계획 등은 **불필요** 판정 — 기존 문서가 이미 커버하거나 1인 프로젝트에 순수 오버헤드.

## 4. 총평

문서 체인의 **골격과 조사 방법론은 견고하다** — 링크 무결, Non-goals 준수, 핵심 수치 다수 일치, 스택 결정 자체는 적대 검증을 통과했다. 그러나 **"개발 전 과정 완료" 주장은 세 가지 이유로 기각된다**: ① 성능 기준기가 물리적으로 부재하고, ② 아키텍처 규칙이 자기모순을 포함해 현 명세로는 첫 모듈부터 막히며, ③ MUST급 요구 1건을 포함한 정합 결함 다수가 문서 간 자기 검증 없이 누적되었다. 모두 수리 가능하며, 수리 범위는 "문서 수정 반나절 + 준비물 몇 시간 + 결정 5건"으로 추산된다.

> 상세 근거·인용·출처는 4개 감사 원문에 있으며, 본 보고서는 그 종합이다.
